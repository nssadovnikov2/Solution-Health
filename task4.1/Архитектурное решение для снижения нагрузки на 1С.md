## Архитектурное решение для снижения нагрузки на 1С
### Решение: Внедрение кэширования результатов проверки полиса (Redis) с TTL = 5 минут.

### Как это работает:

Запрос полиса: API Gateway принимает запрос на проверку полиса.

Проверка кэша: Gateway сначала проверяет Redis по ключу policy:{номер_полиса}.

Кэш-хит (найдено): Возвращает результат из кэша (валиден/невалиден). Обращение к 1С не происходит.

Кэш-мисс (не найдено): Gateway вызывает 1С, получает результат, сохраняет его в Redis с TTL = 5 минут, возвращает клиенту.

Почему это снижает нагрузку:

В часы пик один и тот же полис проверяется многократно (пациент заходит в приложение, выбирает врача, подтверждает запись).

Кэш снимает 80-90% повторных запросов к 1С.

Даже если 1С упала, в кэше остаются последние успешные результаты для часто проверяемых полисов.
