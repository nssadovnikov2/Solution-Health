### Меры защиты каналов передачи данных

| Мера | Описание |
| :--- | :--- |
| **TLS 1.2+ (HTTPS)** | Все данные между мобильным приложением и API Gateway передаются строго по HTTPS с TLS версии не ниже 1.2. Это защищает от перехвата трафика (man-in-the-middle). |
| **Certificate Pinning** | Мобильное приложение имеет встроенный «отпечаток» сертификата API Gateway. Это предотвращает подмену сертификата при атаке на DNS или промежуточные прокси. |
| **Шифрование чувствительных данных в кэше** | Результаты анализов и данные полиса, сохраняемые локально на устройстве (кэш), шифруются (Android: EncryptedSharedPreferences, iOS: Keychain). |
| **Минимизация передачи персональных данных** | В логах API Gateway и сервисов вместо ФИО пациента используется `patient_id` (псевдоним). Полные данные логируются только в защищённом контуре (например, в SIEM). |
| **Защита от SQL-инъекций (существующий дефект)** | Внедрение **параметризованных запросов** во все сервисы, работающие с базой данных (особенно веб-портал, где зафиксирована SQL-инъекция в INT-006). Все строки, поступающие от клиента, проходят валидацию и экранирование. |
| **Ограничение доступа (Network Policies)** | В Kubernetes настраиваются Network Policies, разрешающие входящий трафик к сервисам только от API Gateway. Прямой доступ к внутренним сервисам (CRM, LIS) из внешних сетей заблокирован. |
