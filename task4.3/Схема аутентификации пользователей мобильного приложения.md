## Схема аутентификации пользователей мобильного приложения
Протокол: OAuth 2.0 + OpenID Connect (OIDC)

Почему: OIDC — отраслевой стандарт для аутентификации пользователей. Он позволяет использовать внешних провайдеров (Госуслуги, Яндекс, Google) или собственный Identity Provider (Keycloak). Для «Здоровья+» логично использовать Keycloak как внутренний IDP, с интеграцией с 1С для проверки данных ДМС.

## Схема:

Регистрация/Вход: Пользователь вводит номер телефона или email + пароль (или использует внешнего провайдера). Мобильное приложение отправляет запрос на /auth/login в API Gateway.

Проверка: API Gateway проксирует запрос в Keycloak. Keycloak проверяет учётные данные, привязывает полис ДМС (через интеграцию с 1С) и генерирует JWT-токен (Access Token) и Refresh Token.

Использование токена: Приложение хранит Access Token в защищённом хранилище (Android: EncryptedSharedPreferences, iOS: Keychain). При каждом запросе к API токен передаётся в заголовке: Authorization: Bearer <token>.

Обновление (Refresh): При истечении Access Token (например, через 15 минут) приложение использует Refresh Token для получения новой пары токенов без повторного ввода логина.

Выход (Logout): Приложение отправляет запрос на /auth/logout, Keycloak инвалидирует Refresh Token.
